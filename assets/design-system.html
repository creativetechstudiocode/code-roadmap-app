Layout Patterns

How pages are structured, at two zoom levels.

Page typeStructure
HomepageLogo bar → hero (eyebrow, gradient title, subtitle, search, filters) → category sections, each a labeled divider + card grid
Roadmap detailEyebrow + title + subtitle → progress bar + legend → vertical waypoint trail → summit banner on completion
Reference guideNav bar → sticky sidebar of grouped topics (dropdown on mobile) + reading panel → terminal switcher → per-topic key points, steps, tables, and callouts

Card grids use repeat(auto-fill, minmax(260px, 1fr)) so they reflow from 3 columns down to 1 without a breakpoint rewrite.

06

Voice & Copy

Audience is curious kids, roughly 8–16, plus parents skimming over their shoulder.

  • Plain, warm, active voice — no jargon without immediately explaining it
  • Titles describe the outcome ("Build Your First Webpage"), not the tech ("HTML/CSS Module 1")
  • Descriptions are one sentence, under ~20 words
  • Buttons say the action: "Start", not "Begin Learning Path"
  • Numbers over adjectives: "6 steps" beats "quick and easy"
07

Do / Don't

Do

Alternate track-orange and track-cyan across cards in a grid so the page has rhythm.

Don't

Introduce a third accent color — every UI moment is either orange, cyan, or neutral ink.

Do

Keep card copy to one sentence. If a roadmap needs more explaining, that's what the detail page is for.

Don't

Stack more than two badges/tags on a single card — it starts to look cluttered fast.

Do

Use JetBrains Mono for anything that reads like data: counts, timestamps, statuses.

Don't

Set body paragraphs in Chakra Petch — it's a display face and gets hard to read at length.

08

Building a New Page

There are two page templates. Pick based on the shape of the content, not the topic — the same subject could be either.

template-roadmap.html

A start-to-finish trail

One ordered path you follow top to bottom, checking off steps as you go. Has a progress bar, checkable waypoints, and saved progress. Use when there's a single correct sequence with a finish line — "Build a Full-Stack App on Cloudflare," "Python From Scratch."

template-guide-roadmap.html

A reference you jump around

A sidebar of independent topics you look up in any order, with a terminal switcher for commands. No progress tracking — it's a lookup tool, not a path. Use for task-based references — "Working with Git & GitHub," "Working with Cloudflare."

The quick test: if someone would start at the top and work down once, it's a roadmap. If they'd come back repeatedly to look up one thing, it's a guide.

Roadmap pages — copy template-roadmap.html rather than building from scratch or copying an existing roadmap page. It has every component pre-wired (progress bar, waypoint trail, copy buttons, localStorage persistence) and marks every spot you need to edit with an EDIT: comment, plus one example of each step type (local / cloud / manual / done) in the STEPS array.

Checklist for a new roadmap page
  • Copy template-roadmap.html, don't start from a blank file
  • Keep the new file in the /pages/ folder; it links /assets/styles.css by absolute path, so there's no per-page stylesheet to manage
  • Give it a unique PROGRESS_KEY — reusing one from another page overwrites that page's saved progress
  • Title on the roadmap page matches the card title on the homepage, word for word
  • Fill in the STEPS array, delete the sample steps, keep descriptions to 1–3 sentences
  • Add a card for it on index.html, in the right category grid, with the real step count
  • If it has no single "finish line" moment, delete the summit banner div instead of leaving it unused

Guide pages — copy template-guide-roadmap.html. It has the sidebar, terminal switcher, and all four content pieces (key-points callout, command blocks, comparison tables, info/warn callouts) pre-wired, with the object shapes documented in a comment at the top of the file. You write content into a TOPICS array — no HTML per topic.

Checklist for a new guide page
  • Copy template-guide-roadmap.html, don't start from a blank file
  • Edit the four EDIT: spots: tab title, sidebar label, main heading, intro paragraph
  • Fill in the TOPICS array; give each topic a group and they auto-sort into sidebar sections
  • Keep every command that's the same on all terminals as { code: '…' } — only add a SHELL entry for genuine native-shell differences
  • Delete the sample topics once your real ones are in
  • Add a card for it on index.html with a Guide tag (not a difficulty)
